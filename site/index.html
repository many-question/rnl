01 · 是什么

网表定义电路，RNL 描述怎样理解和呈现它。

RNL（Rich Netlist，富网表）不是一种新的网表格式。它是写在现有网表注释里的一层描述：这些器件构成什么结构，设计者希望怎么摆，图上怎么画。

原生网表定义电路；Rich Netlist 描述如何理解和呈现这个电路。语义描述可以独立于几何存在，几何可以逐步细化，但两者都不能重新定义电路。

RNL 原则草案 · 定位与总纲

网表管的

电气事实，唯一来源

ota5t · 五管运放悬停或点击两侧条目

RNL 管的

理解与呈现，只引用不改写

藏在注释里

写在宿主网表的合法注释里，比如 SPICE 的 * @RNL {…}。仿真器把它当普通注释，不需要先剥掉。

不改电路

只能引用网表里的器件、网络和端子，不能新建器件、连接或参数。图上的线交叉、重叠，都不算连接。

粒度随意

可以只写一句“M1、M2 是差分对”，也可以写到每个坐标和拐点，两种写法能在同一个文件里混用。

RNL 不是

  • 又一种网表语言
  • 第二份连接表
  • 规定唯一画法的格式
  • 像素级的图片存档

02 · 为什么

网表和原理图，各缺一半。

仿真靠网表，看懂电路靠原理图。设计者每天在这两种表示之间来回，而它们各有短板。

要做的事网表原理图（专有格式）网表 + RNL
仿真器直接读 本来就是给它的 要先导出网表 RNL 只是注释
一眼看懂电路结构 只有一行行文字 看得懂 查看器画出来
纯文本，能 diff、能进 Git 是 二进制数据库 是
AI 能读、能写 文本 图形格式 画法也是文本
不装原来的工具也能打开 任何文本编辑器 要同款软件和版本 任何 RNL 查看器
带着设计意图 没有 只在画面里，机器读不出 差分对、对称都是语句
电路只有一份真相 是 图和网表可能对不上 连接只看网表

现在的几种补救办法

手工重画

费时，而且网表一改，图又得跟着再画一遍。

自动生成

只知道连接，不知道结构：线都连上了，却看不出哪两个管子是一对。

截图、导出图片

图有了，电路没了：不能仿真，也没法再改。

专有格式

只能在原来的工具里打开；换工具、换版本，往往要从头再来。

RNL 的思路：不另起一个文件，把画法写回网表本身。

05 · 工具链

RNL 工具链：读、解、画、改。

规划中的工具链把“读懂 RNL”和“把意图变成坐标”分成独立模块：没有求解器也能看图，需要时再求解。选一条路径看数据怎么流动，点一个模块看它做什么。

前端外壳 Web 应用 · React + Vite 桌面应用 · Tauri 2 手机浏览器 共用一套前端代码；核心模块用 Rust 编写，编译到 WASM，通过 npm 的 @rich-netlist 包分发。

06 · 设计原则

语法还在变，这几条原则已经定下。

它们来自 RNL 原则草案，是后续所有语法讨论的前提。

SPICE
Spectre
仿真器：注释，跳过RNL 工具：读取

住在注释里

RNL 只写在宿主网表的合法注释里。仿真器把它当注释，不需要先剥离；不同网表只是注释前缀不同。

电路只有一份真相

器件、参数、连接只由网表定义。RNL 可以引用它们，不能改写；图上的线交叉或重叠，也不产生连接。

语义和几何，粒度随意

可以只写“这是差分对”，也可以只写一条对齐约束，或者写到精确坐标；几种粒度能在同一个对象上混写。

描述意图，不规定唯一画法

“沿 x 排序”没有规定从左到右还是从右到左。满足意图的画法都算对，由求解器按风格挑选。

后写的覆盖先写的

同一属性写了两次，以后写的为准；没冲突的部分都保留：x 改成 14，y 还是 20。修改既可以就地改，也可以追加在后面。

检查工具：1 个错误查看器：照常显示

出错只影响这一句

写错的语句被忽略，依赖它的语句随之失效，其余照常生效。检查工具报告错误的位置，查看器照常显示。

机器只读正式记号：M2 照样会移到 x = 30。

人和模型都读得懂

正式记号之间可以夹说明文字，方便没有渲染器时阅读；但说明文字没有含义，写 “do not move” 也挡不住后面的 @AT。

作用域跟着电路层次走

写在子电路里的描述只管这个子电路。$ 开头的定义沿层级向下继承、可以被覆盖；% 开头的名字只在本层。

另外，RNL 是纯数据：处理时不执行任何代码，也不会因为出现某个类型名就自动联网下载。

07 · 语言框架

RNL 语言长什么样。

以下写法来自正在进行的语言讨论（1.16 方案，2026-09-29），还没有写进 spec/ 里的语法草案；解释器原型已经验证它能实现、没有自相矛盾，关键字名和细节仍会调整。

一条语句的解剖

关键字 网表对象 本层名字 定义 说明文字
* @RNL(source="user") { * Input pair, %dp1 = #M1(in_p) and #M2(in_n) are @AS $DIFFPAIR; * }
提示把鼠标放到任意一段上，或用 Tab 键逐个查看。

引用记号

一眼就能分清谁是网表里的东西、谁是 RNL 自己的东西。

#M1网表里的器件或实例只引用，不创建
&vss网络网表里的节点
#M1:d端子按端子名，或按序号（从 1 起）
#:inp本层子电路的端口由 .subckt 定义
%dp1本层的 RNL 对象只在这一层可见
$DIFFPAIR定义类型、符号、样式、模式；向下继承
<10, _>点“_” 表示这一轴留给求解器
?a模板里的空位套用模板时填入
#M1::name子对象比如器件名标签

语句的几种形态

对象 + 关键字

把 M1 放在 (10, 20)。只写 x 或只写 y 也行，没写的一轴保持自由。

集合

花括号是有序的一组对象：M1、M2 的 y 坐标相同。

角色

括号紧跟对象，说明它在这句里的角色；and、are 是说明文字。

命名

给结果起名，之后可以引用 %g0，例如给它定位置。

管道

前一段的结果交给下一段：先放好位置，再左右镜像。

记录

一段记录，里面的语句用分号分开；source 标明是谁写的。

关键字家族

点一个关键字看它的用途和写法。

电路语义
布局意图
精确几何
虚元件与外观
定义
文件与记录

四种布局原子

布局意图最终都落到四种关系上，都作用于投影坐标（x、y，原型里还有 x+y、x−y 两条对角线）。它们不规定方向，只有 signed 的距离规定先后。

对齐：y 坐标相同，排成一行。

顺序：沿 x 严格排开，正序倒序都算满足。

匀布：相邻间距相等，比如让尾管居中。

距离：B 在 A 右边至少 3 格；absolute 模式则不管先后。

一层电路是怎样生效的

整层读完以后按固定阶段处理。所以语句可以先用后定义，出错的语句只影响自己。

常见问题

加了 RNL 的网表，仿真器会报错吗？

不会。RNL 只写在宿主网表的合法注释里，仿真器当普通注释跳过，不需要预处理。具体用哪个标记在各家仿真器里都安全，还在调研和验证。

RNL 会改我的电路吗？

不会。器件、参数和连接只由网表定义，RNL 只能引用它们。图上的线交叉、重叠，都不会产生连接；只改 RNL 时，网表正文原样保留。

一定要写坐标吗？

不用。只写“M1、M2 是差分对，关于中轴对称”也是合法、有用的描述；坐标可以交给求解器，也可以以后逐步补上。

同一份 RNL，不同工具画出来一样吗？

写了精确几何的部分会一致；只写了意图的部分，不同求解器可以给出不同、但都满足意图的画法。RNL 不承诺像素级一致。

和 Virtuoso、KiCad 的原理图文件有什么不同？

那些是各个工具自己的图形格式，和网表分开保存。RNL 附着在网表上，任何支持它的工具都能读；查看器也不自带元件库，符号本身就用 RNL 定义。

为什么常提到 AI？

大模型擅长读写网表这样的文本。RNL 让“画法”也变成文本，模型能直接写出、局部修改。语句之间可以夹说明文字方便人读，但说明文字不改变机器含义。

现在能用吗？

还不能当产品用。语言在逐条讨论，已有布局求解和解释器原型；正式的运行库、求解器和查看器在规划中。
